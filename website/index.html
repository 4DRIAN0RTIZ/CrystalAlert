Crystal.fire(options)

Open a modal alert or confirmation. It always returns a Promise. If another modal is open, new calls wait in FIFO order instead of replacing the active dialog.

title
Title, rendered as plain text
text / html
Plain text or trusted HTML content
icon / iconHtml
Built-in or custom icon
confirmButtonText
Label for the confirm button
showCancelButton
Add a cancel button; result is false
showCloseButton
Add an X button; result is null
preConfirm
Sync or async callback before confirming
timer / timerProgressBar
Auto-close in ms, optionally showing progress
onOpen / onClose
Callbacks when the modal opens or finishes closing

Alert or confirmation

const result = await Crystal.fire({
  title: 'Delete this project?',
  text: 'This action cannot be undone.',
  icon: 'warning',
  showCancelButton: true,
  confirmButtonText: 'Delete'
});

if (result === true) {
  // The user confirmed.
} else {
  // The user cancelled or closed the modal.
}

Async confirmation

preConfirm can return a value or a Promise. The confirm button shows a loading state while it is pending; return a message from inputValidator to keep an input prompt open.

const result = await Crystal.fire({
  title: 'Publish changes?',
  icon: 'success',
  preConfirm: async () => {
    await publishChanges();
    return { published: true };
  },
  onClose: (value) => handleClosedModal(value)
});

Results: confirmation resolves to true (or the value returned by preConfirm), cancel resolves to false, the close button/backdrop/ESC resolves to null, and a timer resolves to { dismiss: 'timer' }.

Crystal.toast(options)

Display a non-blocking notification. Toasts stack without blocking the page and dismiss themselves after duration.

title
The toast title, rendered as plain text
text / html
Plain text or trusted HTML content
icon / iconHtml
Built-in or custom icon
duration
Auto-dismiss in ms; use 0 for a persistent toast
position
top-right, top-left, bottom-right, or bottom-left
pauseOnHover
Pause the timer while the pointer is over the toast
showCloseButton
Show a button that dismisses the toast
onClose
Called after the exit animation with the dismiss reason
returns
A handle: { id, close(), update(), closed }

Update one notification

Use a handle when one operation changes state, such as “Uploading” becoming “Uploaded”. This updates the existing toast instead of creating a second one.

const uploadToast = Crystal.toast({
  title: 'Uploading file',
  text: 'Please wait...',
  icon: 'info',
  duration: 0
});

// Call this when the upload finishes.
uploadToast.update({
  title: 'File uploaded',
  text: 'The operation completed successfully.',
  icon: 'success',
  duration: 3000
});

// Close it programmatically when needed.
uploadToast.close();

Pause, close, and await dismissal

Use pauseOnHover for messages that need time to read. A close button is optional, and closed resolves after the exit animation with the reason for dismissal.

const toast = Crystal.toast({
  title: 'Session expires soon',
  text: 'Move the pointer over this toast to pause it.',
  duration: 5000,
  pauseOnHover: true,
  showCloseButton: true,
  onClose: (reason) => handleDismissedToast(reason)
});

const reason = await toast.closed;
// reason: 'timer', 'button', 'click', or 'programmatic'

Close by id or close all

close() and the singleton methods keep the exit animation before removing the toast.

const toast = Crystal.toast({
  title: 'Needs attention',
  duration: 0
});

Crystal.closeToast(toast.id); // close one
Crystal.closeAllToasts();     // close every active toast

Use the playground below for basic toast appearance, position, icon, and timer behavior. The examples above cover programmatic lifecycle control.

Crystal.prompt(title, options)

Open a modal with an input and resolve the Promise with the submitted value. It is a convenience wrapper around Crystal.fire().

input
text, email, password, number, textarea, select, or checkbox
inputPlaceholder
Placeholder for text-like inputs
inputValue
Initial text, number, or checkbox value
inputOptions
Options for select: strings or { value, label } objects
inputValidator
Return an error message to block submit, or an empty string to allow it
showCancelButton
Allow dismissal without submitting

Validate an email

const email = await Crystal.prompt('Subscribe', {
  input: 'email',
  inputPlaceholder: 'you@example.com',
  showCancelButton: true,
  inputValidator: (value) => {
    return value.includes('@') ? '' : 'Enter a valid email.';
  }
});

if (email) subscribe(email);

Select from fixed options

const frequency = await Crystal.prompt('Send me', {
  input: 'select',
  inputOptions: [
    { value: 'daily', label: 'Daily digest' },
    { value: 'weekly', label: 'Weekly summary' }
  ],
  inputValue: 'daily'
});

Dismissal: cancel, ESC, the close button, or the backdrop returns a falsy result. Use inputValidator for client-side validation before accepting the value.

Crystal.setTheme(name)

Load one optional CSS theme at runtime. The current theme link is replaced instead of duplicated, and the method returns a Promise that resolves after the stylesheet loads.

setTheme(name)
default/light, dark, minimal, or a custom theme name
setThemePath(path)
Set the directory containing theme CSS files
getTheme()
Read the active theme name
returns
Promise; rejects when the stylesheet cannot be loaded

Use the built-in themes

Crystal.setThemePath('dist/themes/');

await Crystal.setTheme('dark');
const activeTheme = Crystal.getTheme(); // 'dark'

await Crystal.setTheme('minimal');
await Crystal.setTheme('default'); // remove the optional theme

Load a custom theme

A custom theme is a CSS file named crystal-alert-brand.css in the configured theme path. It should override the library's --ca-* variables.

:root {
  --ca-accent-color: #8b5cf6;
  --ca-bg-color: rgba(30, 20, 60, 0.9);
}
Crystal.setThemePath('/assets/themes/');
await Crystal.setTheme('brand');

Tip: call setThemePath() once during setup. Use try/catch around setTheme() when the theme file may be unavailable.
